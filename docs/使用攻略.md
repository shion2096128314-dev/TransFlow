# TransFlow 使用攻略

从零到手，到汉化一整面墙的漫画，这篇够用。

---

## 0. 五分钟装好（验收清单）

1. 装 Python 3.10+（勾选 Add to PATH）
2. 双击 `install.bat`，等到出现 `all modules OK`
3. 装 Ollama，执行 `ollama pull maternion/hy-mt2:1.8b`（约 1.1G）
4. **验收**：拖一张测试图到 `TransFlow-HyMT2.bat` 上，9 秒左右出结果就是全链路通了

> 安装中途失败的，90% 是网络。国内用阿里云源重装：
> `.venv\Scripts\python.exe -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple/`

## 1. 场景：翻一本漫画（最常用）

**三步**：

1. 找到漫画文件夹（里面直接是一张张图片，可以有子目录）
2. **按住文件夹拖到 `TransFlow-HyMT2.bat` 图标上松手**（是拖拽，不是双击）
3. 黑窗口显示进度，跑完停在"请按任意键继续"——这时候再去 `源文件夹\translated\` 拿成品

**质量抽查**（建议每次换新漫画时做一次）：

- 打开一张成品，看气泡里的中文对不对
- 想看原文对照？翻 `translated\` 里的 `*.json`，每块的原文/译文都在里面
- 想要双语对照图？给 bat 的命令加上 `--bilingual`（见第 7 节）

**速度参考**：混元约 4 秒/张。一本 44 页的漫画约 3 分钟。

## 2. 场景：翻整个漫画库（批量 + 断点续传）

```bash
python _batch_files.py "D:\漫画\库A" "D:\漫画\库B"
```

这个模式是为一墙漫画设计的：

- **逐张翻**：每张都有日志，带 ETA，进度看得见
- **断点续传**：输出已存在就跳过——翻到一半想关机？直接关。下次重跑同一条命令，从断点继续
- **模型哨兵**：每张图前检查 Ollama 模型在不在线，挂了立即停，不会傻傻产出一堆没翻译的图

**验收方法**（翻完对账）：

```bash
# 每个文件夹的成品数应该 = 源图数
```

曾经用它在 23 分钟里翻完 319 张，0 失败。

## 3. 场景：导出译文对照表

翻译时加了 `--save-json` 的话，每张图都有一份 json 记录。想汇总过稿：

**把翻译输出文件夹拖到 `TransFlow-EXPORT.bat` 上**，生成两个文件放在该文件夹里：

- `_TransFlow_译文对照.txt` —— 按页分组，肉眼过稿用
- `_TransFlow_译文对照.csv` —— 带 BOM，Excel 双击打开不乱码，可筛选排序

**什么时候用**：交稿前全文校对、统计术语、给协作者复核。

---

## 4. 场景：清理 json

json 的使命是「复查 + 导对照表」。对照表导出后，json 就没用了，留着占地：

```bash
python _recycle_json.py "D:\漫画\第01话\translated"
```

- 送进**回收站**（可恢复），不是永久删除
- 每批 10 个、批后验证，中途出错立即停

**删了会怎样**：以后再想导对照表，得重跑翻译才能有 json。所以顺序建议：**先导出对照表，再删 json**。

## 5. 模型攻略：翻得快还是翻得野？

| | 混元 Hy-MT2-1.8B | Qwen3-8B 破限版 |
|---|---|---|
| 速度 | **约 4 秒/张** | 约 25-30 秒/张 |
| 44 页 | 约 3 分钟 | 约 20 分钟 |
| 翻译质量 | 专业翻译模型，稳 | 通用模型，偶尔更"活" |
| 拒译 | 基本不拒 | 原版会拒，破限版解决 |

**结论：日常大批量用混元，一条命令都不用改。** Qwen 的定位是备胎——只有混元搞不定的片段（极少见），才值得把那张图单独挑出来用 Qwen 慢翻。

换模型：编辑 bat 把 `--model maternion/hy-mt2:1.8b` 改成 `--model qwen3-8b-ab` 即可（模型要先 `ollama pull`）。

## 6. 排障手册

### 拖上去窗口一闪就没了

按顺序查三样：

1. `logs\bat_trace.log` 有没有新行——**没有**：系统没让 bat 执行（右键 bat → 属性 → 底部"解除锁定"）
2. **有行**：bat 跑起来了，问题在 python——看 `logs\run.log` 最后几行
3. 最常见的根因：**bat 文件名或内容里出现了中文**。cmd 按系统代码页解析命令，中文在非中文代码页机器上会变乱码碎片，把命令切碎。本项目的规矩：bat 文件名 + 内容全 ASCII，中文说明全放文档里。

### 日志显示 "no images found" 但文件夹里明明有图

九成是**路径里带方括号**：`xxx-[BNO (...)]` 这种文件夹名里，`glob` 会把 `[...]` 当通配符字符类，导致一个文件都匹配不到。本项目已用 `glob.escape` 修复；自己写脚本时记得：**给路径拼 glob 模式前必须 escape**。

### PowerShell / .NET 工具报"路径过长"

真实路径超过 260 字符（常见于超长的漫画文件夹名）。Python 程序无感；PowerShell 命令会炸。要么传 8.3 短路径（`TRANSL~1`），要么用 Python 干这活。

### 有些页没有 json

纯画面页（没有任何文字）会直接复制原图当成品，不出 json。正常现象，不是漏翻。

### 翻译质量不对

- OCR 识别错了 → 翻译必错。艺术字/手写体是 OCR 的天敌
- 一个气泡里句子太多时，合并翻译偶尔会"理顺"语序，与原文断句不完全对应
- 暗底白字/亮底黑字会自动切换；遇到描边看不清的，用 `--font-color` 手动指定

## 7. 高手向

**改字体/颜色**：bat 命令末尾加 `--font "C:\Fonts\xxx.ttf" --font-color 30,30,30`

**竖排漫画**：加 `--vertical`

**成品单独放一个盘**（源目录保持干净）：用 toFolder 系列 bat；或命令行 `--outroot "D:\已汉化漫画"`

**双语校对流**：加 `--bilingual` 出双语图，原文位置压着译文，校对完再决定删不删

**只要成品不要双语/json**：bat 里默认就没带这俩参数；带上的话去掉 `--bilingual --save-json` 即可

**调试别忘清缓存**：改了 `core.py` 没生效？先删 `__pycache__` 再跑

## 8. 实测性能参考（RTX 4050 笔记本 + 混元 1.8B）

| 场景 | 数据 |
|---|---|
| 单张（2 个文本块） | 9 秒 |
| 单张（15+ 个文本块） | 6-9 秒 |
| 44 页漫画 | 183 秒 |
| 319 页批量（含 9 个文件夹） | 23 分钟 |
| 无文字页 | < 1 秒（直接复制） |

一张 900x560 的图，模型预热后约 5-6 秒。瓶颈在翻译模型，OCR 和渲染都是秒级。
